# 实施与验收

## 阶段

| 阶段 | 范围 | 退出条件 |
| --- | --- | --- |
| M0 初始化 | 当前骨架、协议、中文文档、just、CI | 三端编解码和格式检查、包构建、健康检查通过 |
| M1 可靠通知 | 数据库迁移、鉴权适配、幂等、Outbox、历史和同步、通知 SDK | 断网/崩溃/响应丢失不漏通知；相同意图不重复创建 |
| M2 实时与多端 | WS、持久本地库、已读、设备、推送 | 重连无订阅空窗；账号隔离；真机推送与冷启动导航 |
| M3 基础 IM | 单聊、群、媒体、回复、撤回、会话管理 | 角色权限、群生命周期、媒体访问及多端行为通过 |
| M4 高级功能 | 编辑、搜索、回应、转发、TTL、治理、Webhook、大群 | 完整功能矩阵逐项验收，负载和故障恢复有证据 |

## 横向验收场景

- **跨语言**：共享合法/非法样例、大序号、未知类型、新可选字段、协议主版本不兼容。
- **写入一致性**：并发重复发送、同键不同内容、事务回滚、提交后断连、Worker 重启。
- **同步一致性**：握手同时新写入、并发事务反序提交、乱序/重复、慢消费者、游标过期、撤回后快照。
- **多设备**：A 已读后 B 更新、设备注销、账号切换时旧响应到达、浏览器多标签。
- **群权限**：退群/禁言与发送并发、管理员越权、新成员历史、解散后附件和搜索。
- **媒体**：断点/失败上传、扫描未完成、恶意文件、签名过期、跨会话转发权限。
- **推送**：前台/后台/强退、token 轮换、权限拒绝、免打扰、冷启动、重复点击、账号不匹配。
- **运维**：Redis 不可用、数据库恢复、Outbox 积压、推送故障、Webhook 死信、备份恢复。

## 性能基线

压测前记录目标在线设备、每秒消息、群规模、消息大小、离线时间、扇出分布及数据库配置；分别测提交延迟、在线投递延迟和离线追赶时间。结果应包含 p50/p95/p99、错误率和资源占用。初始化阶段不使用未经测量的容量数字作为承诺。

## 兼容与发布验收

构建成功不等于可集成：每次正式发布须从产物安装到独立示例工程，验证 SDK 导出 API 和最小使用方式。Schema 与文档变更同时更新契约测试。真实通知接入 sf-app 时保留旧 messageId 映射，由同一可靠存储供新旧接口读取，避免双写产生不同消息事实。
